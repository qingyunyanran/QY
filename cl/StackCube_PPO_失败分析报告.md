# StackCube-v1 PPO 训练失败分析

## 训练配置

| 参数 | 值 |
|------|-----|
| 环境 | StackCube-v1 |
| 算法 | PPO (SB3) |
| obs_mode | state_dict |
| control_mode | pd_ee_delta_pose |
| 并行环境数 | 8 |
| 训练步数 | 5,000,000 |
| 网络结构 | 256-256-256 MLP + Tanh |
| n_steps | 2048 |
| gamma | 0.99 |
| learning_rate | 3e-4 |
| entropy_coef | 0.01 |
| max_episode_steps | 300 |

## 训练结果

- **最终成功率**: 0%（50 次评估全部失败）
- **训练时长**: ~15 小时（CPU 模式）
- **评估奖励**: 377.88 ± 53.57
- **评估 Episode 长度**: 300.00 ± 0.00（每次跑满最大步数）

## 策略行为分析（10 个 Episode）

### 动作模式

所有 episode 中，策略输出的动作高度一致，呈现**固定动作模式**：

| 动作维度 | 均值范围 | 标准差 | 说明 |
|---------|---------|--------|------|
| action[0] | 0.87 ~ 0.99 | 0.10 ~ 0.48 | 几乎恒定 → 一直往右 |
| action[1] | -0.99 ~ -0.89 | 0.13 ~ 0.42 | 几乎恒定 → 一直往后 |
| action[3] | -1.0 ~ 0.96 | 0.0 ~ 0.51 | 部分 episode 恒为 -1 |
| action[4] | -1.0 ~ 0.76 | 0.0 ~ 0.54 | 部分 episode 恒为 -1 或 0 |

**关键发现**：多个动作维度的标准差为 0 或极低（<0.05），说明这些维度完全不看观测就输出固定值。策略已坍缩。

### 熵变化

- 初始熵: -9.94
- 最终熵: -16.95
- **下降幅度**: -7.01

熵下降过大说明策略过早收敛到确定性行为，丧失了探索能力。

### 奖励分析

- 大部分 episode 平均单步奖励: 1.2 ~ 1.6
- Episode 6 奖励异常高: 2.57/step（总奖励 771）
- 但所有 episode 均未成功

说明模型学到了"多动作"能获得更多奖励，但没有学到正确动作。

## 失败根因

### 1. 并行环境数不足
- 官方使用 512 个并行环境（GPU 模式）
- 本实验仅 8 个环境
- 采样多样性不足，策略容易坍缩

### 2. 任务复杂度高
- StackCube 需要多步协调：接近目标方块 → 抓取 → 抬起 → 对准另一方块 → 放下
- 纯随机探索几乎不可能触发首次成功
- 没有成功样本就没有正向梯度信号

### 3. 熵正则化不足
- entropy_coef = 0.01 偏低
- 策略在训练早期就坍缩为固定动作模式
- 之后无法恢复探索

### 4. CPU 环境限制
- 无法使用 ManiSkill 官方 GPU 并行（需要 CUDA）
- 训练效率低 64 倍以上（8 envs vs 512 envs）
- 5M 步需要 15 小时，无法尝试更大规模训练

## 结论

在 CPU 环境下（8 并行环境），纯 PPO 从随机初始化训练 StackCube-v1 **不可行**。
策略在训练早期坍缩为固定动作模式，无法探索到成功策略。

**建议方案**：
1. 使用 BC 预训练获得初始策略（已有 85% 成功率的 BC 模型）
2. 在 BC 基础上进行 RL 微调
3. 或直接使用 BC 策略进行持续学习实验
