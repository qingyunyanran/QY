# PlugCharger-v1 失败根因（已定位）

## 结论速览

| 事实 | 数值 | 含义 |
|---|---|---|
| 官方 motion-planning solver 成功率 | **70~81%**（seed 5000-5009 实测 7/10、8/10） | 任务本身可解，solver 是可靠专家 |
| solver 成功时 `obj_to_goal_dist` | **0.5~3.4 mm** | 真正插进插座 |
| solver 失败时 `min dist` | **16.0~16.8 mm**（== 初始距离） | charger 根本没被拿起/对准 |
| 自写的 8 段推进版 `_sol_plug.py` | **10%**（1/10） | 分段 + 中途 `evaluate()` + 回退把插头拉出孔，**不要再用它采数据** |
| demo 动作 ↔ 真实 dq 比例 | `dq = 0.03929 × act`，7 关节完全一致（相关系数 >0.9985） | **动作转换正确**，不是尺度 bug |
| env `pd_joint_delta_pos` 实测尺度 | joint4/5/6 → 0.0392，joint0 → 0.024，joint1 → 0.0264 | 与 demo 的 0.0393 一致 ✅ |
| demo 规模 | 246 eps / 22357 帧 / 66 维 / `|act|` 均值 0.330 | 数据量够 |

**动作管线没问题，问题在 BC 策略本身。**


三个硬事实：

1. **t=0 的 obs 与 demo 第 0 帧完全一致（nn dist=0.00），但策略输出非零而 demo 是精确的全 0。**
   说明 BC 在训练分布内就已经有 ~0.14 的动作偏差 —— 不是"泛化问题"，是**拟合本身不够**。
2. **闭环第 20 步之内 nn 距离就从 0 涨到 12+**，第 45 步起匹配到完全不相干的 episode。
   策略轨迹一旦偏离 demo 流形，最近邻失真，误差自我放大。
3. **`dg` 全程不变 = 机械臂从头到尾没接触到 charger。**
   所以"插入差 2mm"是伪命题：**真正的失败在更早的接近/抓取阶段**。

## 根因

demo 有**多模态**：同一 obs（尤其 reset 后与接近阶段）在不同 seed 下对应的后续动作不同（抓取 yaw 偏移、接近方向细节）。
用**均值 MSE** 回归多模态动作分布 ⇒ 网络输出被平均化：

- 单帧误差降到 MSE≈0.008 就压不动了（RMSE 0.089 vs `|act|` 0.26，即 34% 相对误差）
- 幅度被系统性压缩（joint0 学不出 0.67，只给 0.02~0.13）
- 开环复制 demo 也走不完，闭环必然漂移

这解释了此前所有失败现象：BC 闭环停在外围、PPO 从 BC 初始化仍然 0%、注入池状态离阈值 2~7mm 且"任何动作都让它变远"（其实池状态本身已经不在可成功的流形上）。

## 已经被排除的假设

- ❌ 动作尺度/坐标系错误（实测一致）
- ❌ demo 质量差（solver 70~81%，末帧 0.5~3.4 mm）
- ❌ 观测维度/扩维 bug（66 维 bit-exact，48 维段布局不变）
- ❌ 注入池代码 bug（已修 5 处，注入后仍需"动作正确"才能成功）
- ❌ 噪声增广 / 末段过采样（`bc_plg66_w5`、`w10` 闭环仍 0%，avg_r -7.6~-7.9）

## 三条可选路线

### A. BC 换损失：高斯 NLL / 混合密度（解决多模态）
`actor_mean` 换成输出 `(mu, log_sigma)` 的高斯头，损失 `-log N(a_demo | mu, sigma)`；
或直接 Mixture Density Network（K=4~8 个高斯）。
**预期**：单帧误差显著下降，闭环能走完接近阶段。**成本**：改网络 + 重训 BC（~30-60 min）。

### B. 真 DAgger（在线，用最近邻当专家）
用当前策略跑 episode，每步取 demo 最近邻（阈值 5σ 内才采）动作作标签，混合后重训，迭代 5 轮。
**预期**：直接修补 OOD 区域，最对症。**风险**：最近邻在早期就失真（t=20 已 12σ），需要先在 A 之后才有意义。

### C. 换表示：Action Chunking（一次输出未来 K=8 步动作）
降低多模态性（短序列内歧义小）+ 抑制误差累积，是 ACT/扩散策略的标准做法。
**成本**最高，但对"多模态 + 误差累积"这一对病根同时有效。

## 建议

**先 A 后 B**：A 把单帧误差压到量级以下（是 B 的前提），B 修正闭环分布漂移。
C 作为两者都无效时的兜底。

## 后续修正（2026-11-12，重要）

上面把根因归为"BC 多模态"，**这个结论不完整**。本轮把闭环拆到逐环节后，
真正的头号原因是**几何管线错了**，不是学习能力不够。抓取"从未发生"（`dg` 恒 155 mm）
是因为下面三处硬错误，修掉后解析式抓取 4/4 全中（`|grasp| = 0.005 m`）：

1. **观测四元数切片**：quat 在 `[42:46]`，旧代码取 `o[39:46]` 7 维喂给 `_R()` ⇒ 姿态全错。
2. **IK 坐标系**：必须用 **base frame**（`B = inv(robot.pose)`），world frame 实测 100% `IK Failed`。
3. **夹爪安装旋转**：`q_grasp = qmult(q_charger, REL_QUAT)`，
   `REL_QUAT = [-0.000205, 0.991622, 0.000165, 0.129171]`（wxyz，中位偏差 0.53°）。
   不建模则与 reset 姿态差 180°，reset 处 IK 必失败。

另外三个数值根因：`n_init_qpos=1` + `sol[0]` 取到远分支导致瞬移 0.28 m（改多采样取最近解）；
IK `threshold` 过松（8 mm）使求解器直接返回当前构型、机械臂不动（改 1 mm）；
控制器只跟踪约 40% 指令（`a*0.1 = 2.5·Δq`）。
完整报告与复现脚本见仓库根目录 `REPORT_PLUGCHARGER.md` 与 `plugcharger/`。
